### Findings as reported

**Money**
- **M1. A flight pass can unlock the wrong flight.** `Paywalls.swift:215,301`: `passFlightID` is set before `register`, and also by `show()` when Superwall refuses because a paywall is already up (error 102). Paywall open for A, then a push for B, then buy → the pass is recorded on B and A stays locked. Fix: set it in `onPresent`. *Checked.*
- **M2. A pass that completes with no paywall open is charged but not recorded** (Ask to Buy, app killed mid-purchase). `Paywalls.swift:462`: the flight id is only in memory. Fix: persist it while the purchase is pending. *Plausible.*
- **M3. Restore shows two contradictory alerts.** Superwall's own "restore failed" alert, then the app's "Purchases restored." for anyone without Pro (`SettingsView.swift:42`, `Paywalls.swift:373`). App Review tests this. *Plausible; read from the SDK source.*
- **M4. `flight_passes` rows are trusted from the client.** RLS only checks flight ownership, so a hand-made row unlocks a flight. Design gap, not new.

**Data and in-flight**
- **D1. Background launches skip arming and re-timing reminders.** `AppSync.swift:22`: `onSync` is set only once a window exists. After iOS kills the app, a wake push reloads the flights but doesn't re-time reminders. *Checked.*
- **D2. A scheduled Live Activity keeps the original start time after a delay** (`InFlight.swift:676`); a second alert can follow later.
- **D3. Every sync re-downloads forecasts for every flight ever saved** (`FlightStore.swift:426`): about 80 requests for 40 past flights, on every push and refresh. *Checked.*
- **D4. A sync can put an older gate back after the 5-minute refresh**, giving "Gate B18, was B22" (`FlightStore.swift:555`). *Plausible.*
- **D5. Gate memory is never cleared;** a date change shows "was" from the old day.
- **D6. The 5-minute gate refresh restarts on every return to the app,** so someone checking often never gets a refresh (`BumpCastApp.swift:83`).

**Screens**
- **S1. The map's route line doesn't redraw for a new route.** It only redraws when the point count changes, and every route has 121 points (`TurbulenceMapLayer.swift:113`). *Checked.*
- **S2. Dates more than 6 days out show only the weekday:** "first forecast Tuesday" for a flight 3 weeks away (`Copy.swift:233–261`, `FlightStatusViews.swift:193`). *Checked.*
- **S3. Editing a flight:** "Change" goes to Route, where the button is Cancel, which drops the edit (`AddFlightView.swift:116,154`). *Checked.*
- **S4. Adding from the cancelled-flight card skips the notification prompt and the flight-added moment** (`FlightDetailView.swift:88`).
- **S5. Locked tiles in the air while offline do nothing,** but still say "Unlock…" (`ForecastView.swift:84`).
- **S6. Free users get pilot reports when Superwall isn't configured** (`TurbulenceMapView.swift:440`).
- Copy: "1 minutes" (`ForecastView.swift:578`, `TurbulenceMapView.swift:719`); "75 min" next to "1 h 15 min" on the tiles; "2 h 0 min ago"; "Now · Saved" before saving; "Updated" times in the phone's zone next to airport-local times.
- Unlikely crashes on bad data: a one-point route (`TurbulenceMapView.swift:716`) and a short map grid (`TurbulenceMapLayer.swift:290`, `MapRoute.swift:116`).

**Layout and screen sizes** (the iPhone Duo work)
