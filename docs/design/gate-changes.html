BumpCast · live status · for review · designs only

Gate changes, shown honestly

A changed gate shows as "Gate B22, was B18", the same way a moved time does: the new gate in teal, the old one struck through. "Was" only appears when this phone showed the old gate. From 3 hours before departure until takeoff, the app re-reads status every 5 minutes while it's open and online, with no spinner and no banner. Gate changes stay in the app, with no push, and are free like the rest of live status. Flights with only the published schedule stop saying "On time".

Copy changes

None. Every line on this board is the brief's wording.

1 · Flight card status row

Next flight card and Upcoming rows

One line, in the existing caption style. A known gate comes before its terminal. The card always uses the full form ("Terminal 4", never "T4"). Only the struck part is lighter; the rest of the row is unchanged.

2 · Route header, departure side

The gate line under the departure time

The new gate line is in teal, with the previous one struck through beneath it, in the same full or short form so the two line up. Times never get a struck pair just because the gate moved. The details open by themselves once, the first time the flight is seen after a change, as they do today.

3 · Delayed and gate changed

Version B chosen

When the time and the gate both move, the departure side could carry two struck lines. Version A stacks them. Version B keeps the header as it is today and puts the old gate only in the details.

4 · Details, schedule-only and freshness

When there's less to show

A gate that disappears isn't announced. The details remember what this phone last showed. Flights with only the published schedule say so plainly. This is a common state (110 of 230 departures at JFK in the sample), not an edge case. The age shows under the label only before takeoff, and only when status is still more than 30 minutes old after the in-app refresh.
