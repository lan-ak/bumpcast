# BumpCast website

Static pages for the App Store listing and for Google's and Microsoft's OAuth reviews (Gmail and Outlook import, `docs/release/EMAIL_IMPORT_SETUP.md`). Domain not chosen yet: every link is relative, so the folder works on any domain.

Preview locally: the `site` entry in `.claude/launch.json` (`python3 -m http.server 4173 --directory site`).

## Pages and what they satisfy

| Path | For |
|---|---|
| `/` | Google home page: same app name as the consent screen ("BumpCast"), describes the app and why it reads email, links the privacy policy, no login. Microsoft home page URL |
| `/privacy.html` | App Store privacy URL. Google privacy policy, including the required Limited Use sentence, what email data is read, kept, shared, and how to revoke. Microsoft privacy statement URL |
| `/email.html` | Plain-language explainer of email access (scopes, what leaves the phone, revoke). Linked from the consent flow and the Google submission |

| `/support.html` | App Store support URL |
| `/.well-known/microsoft-identity-association.json` | Microsoft publisher-domain verification. **Replace the zero GUID with the Entra app's Application (client) ID** before deploying |
| `/llms.txt` | Plain Markdown summary of the app and its key features for AI agents and LLM crawlers ([llms.txt](https://llmstxt.org) convention). Keep in step with the App Store description. Its "## Learn" and "## Routes" sections are generated |
| `/llms-full.txt` | Generated: `llms.txt` followed by every Learn explainer and route page in full, for AI agents that want everything in one file |
| `/learn/` | Generated: the app's Learn library ("Turbulence, explained"), one page per explainer. See below |
| `/routes/` | Generated: turbulence by route, one page per popular route, from a year of pilot reports. See below |
| `/learn/*.html.md`, `/routes/*.html.md` | Generated: a clean Markdown copy of each page for AI agents (llms.txt convention: the page's URL plus `.md`) |

| `/picker.js` | The "Find your route" picker on `/routes/` and the home page: From and To, then that route's page (either direction), or, for a pair without a page, a note that the app forecasts any covered flight. Hidden without JavaScript; the links and table still reach every route |
| `/robots.txt` | Lets every crawler in, search engines and AI alike, and points to the sitemap and `llms.txt` |

| `/404.html` | Host not-found page (root-relative links, so it works at any depth) |

## Learn and Routes pages

`/learn/` and `/routes/` are generated by `scripts/build_site.py`, so search engines and AI assistants can read and cite them. Every page has a search title and description, a canonical URL, Open Graph tags, JSON-LD and a Markdown copy. The script also writes `llms-full.txt`, the "## Learn" and "## Routes" sections of `llms.txt`, `sitemap.xml`, and the Learn and Routes sections of the home page (between the `learn:start` and `learn:end` comments). Don't edit files in `site/learn/` or `site/routes/` by hand: they are overwritten, and stray files are deleted. `scripts/publish_site.sh` runs `build_site.py --check` and won't publish stale pages.

```bash
python3 scripts/build_site.py       # rebuild everything above; commit the result
```

### Learn

The app's Learn library. The words come straight from the app: the script reads the explainers in `ios/BumpCast/Views/LearnView.swift`. The diagrams are the app's, drawn as SVG. JSON-LD: `Article` (with `citation`), `FAQPage`, `BreadcrumbList`.

- **Web-only parts**, at the top of the script: `WEB` (slug, search title, summary, and questions that head the app's three sections, such as "What causes clear-air turbulence?") and `MORE` ("In more detail" questions, each citing `SOURCES`: FAA handbooks and AIM, NTSB, 14 CFR). Keep `MORE` to what its sources say; every fact was checked word for word against them on Nov 7, 2026.
- **From the route data**: the clear-air page's winter comparison, the gusty-airport page's gustiest airports, and "Routes over high ground" and "Routes with gusty airports" links.
- After changing an explainer (or `MORE`), bump `UPDATED` in the script. A new explainer needs a `WEB` entry; the script stops until it has one.
- Safari's app banner on each explainer carries `app-argument=bumpcast://learn/<id>`, so **Open** goes straight to that explainer for people who have the app.

### Routes

Where and when pilots reported bumps on popular routes, from a year of airliner pilot reports, plus gusty days at each airport. Data: `scripts/data/routes.json`, made by `scripts/route_data.py` from the Iowa Environmental Mesonet's archive of National Weather Service pilot reports and airport weather reports, using the worker's flight model (`worker/src/smooth_worker/route.py`). JSON-LD: `Article`, `Dataset`, `FAQPage`, `BreadcrumbList`.

- **Refresh the data** (monthly or so; needs network access to `mesonet.agron.iastate.edu`), then rebuild:

  ```bash
  cd worker && uv run python ../scripts/route_data.py    # the last 12 full months; downloads cached in ~/.cache/bumpcast
  cd .. && python3 scripts/build_site.py
  ```

- **Add a route:** add the pair to `ROUTES` in `route_data.py` and refresh. A route needs at least 400 reports near it (`MIN_REPORTS`) for a page; Vancouver–Calgary doesn't have them.
- **Why the pages don't rank routes or quote shares as odds:** how often smooth air gets reported depends on the control center (in the past year, 4% of cruise reports at Washington Center but 45% at Miami Center). So each page compares places and months within its route, leads with counts and places, and says so in "How we made this page".
- **Find your route:** a From/To picker on `/routes/` and the home page (`picker_html` in the script, `picker.js`). A pair without a page gets the app pitch, with the `web-picker` campaign.
- **Phones:** each chart is drawn twice, wide and compact, and CSS shows the one that fits; the routes table becomes one block per route.
- **Gusty** means gusts of 25 kt or more in an hourly airport report, the app's own threshold (`worker/src/smooth_worker/airfield.py`).

### App Store links (counting downloads by page)

Every App Store button on these pages carries a campaign name (`web-learn-<id>`, `web-route-jfk-lax`, `web-routes`). To have App Store Connect count downloads by page (Analytics, Acquisition, Campaigns), set `APP_STORE_PT` at the top of `build_site.py` to the provider token from App Store Connect, and optionally `APP_STORE_PPID` to send visitors to the "Turbulence" custom product page. Then rebuild. Until then, the buttons link to the plain listing.

Look: the app's "Cabin Dawn" mood layer (docs/design/DESIGN_SPEC.md). `sky.js` picks a dawn, day, dusk or night sky from the visitor's clock (dark mode is always night), with glass cards, the wave timeline, water-glass severity glyphs and the breathing orb. No cookies, analytics, third-party scripts or fonts. Fonts are the app's own OFL fonts in `fonts/`.

### Publishing a change

`gh-pages` holds only the built files, with no history worth keeping. From the repo root:

```bash
scripts/publish_site.sh
```

It copies `site/` (minus this README) into a temporary checkout of `gh-pages`, commits and pushes. Pages redeploys in about a minute.

Then tell the search engines: `python3 scripts/indexnow.py` notifies Bing (and other IndexNow engines) of every page in the sitemap. Google reads the sitemap from `robots.txt`; to speed it up, resubmit it in Search Console.
